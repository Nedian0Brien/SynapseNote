# 네이티브 연속 텍스트 편집기 스파이크

## 문제

SynapseNote의 기반을 macOS·iPadOS·iOS 네이티브 앱으로 옮기기로 했고, 편집기는
완전 네이티브·연속 텍스트 방식으로 정했다. 그런데 이 방향이 성립하는지 확인한
근거가 아직 없다. 네이티브 앱 설계 전체가 아래 두 가정에 걸려 있다.

1. **동기화 가정.** 네이티브 앱은 서버 문서의 `Y.Text('source')`(파일 전체 바이트)
   하나만 동기화해도 웹 편집기·에이전트와 같은 문서를 함께 편집할 수 있다.
   근거는 코드에 있다 — 두 공유 타입 사이 변환은 서버 관찰자만 하고
   (`server-observers.ts`), 웹 소스 모드와 `agent-patch`가 이미 `Y.Text`만
   고친다. 다만 Swift 클라이언트로 돌려 본 적은 없다.
2. **편집기 가정.** TextKit 2 텍스트 뷰 하나로 라이브 프리뷰(문법 기호를 숨기고
   서식만 입힘), 네이티브 뷰 삽입(인라인 데이터베이스 등), accordion 접기를
   구현할 수 있다. 셋째는 공식 API로 바로 풀리지 않는다.

둘 중 하나라도 틀리면 편집기 설계를 다시 해야 한다. 파서·데이터베이스·앱 셸에
손대기 전에 이것부터 확인한다.

## 원하는 결과

스파이크 앱과 결과 보고서가 남고, 아래가 확인되어 있다.

1. **동시 편집.** 스파이크 앱과 웹 편집기와 `agent-patch`가 같은 문서를 동시에
   편집한다. 각자의 변경이 다른 쪽에 1초 안에 보인다. 10분 동시 편집 뒤에
   디스크 파일, 앱의 텍스트, 웹 편집기의 소스가 바이트 단위로 같고, 서버 로그에
   bridge invariant 위반이나 충돌 상태가 없다.
2. **라이브 프리뷰.** 제목, 굵게·기울임, 목록, 체크박스, 인용, 코드 블록, 링크가
   서식으로 보이고, 커서가 들어간 부분에서만 문법 기호가 드러난다. 체크박스를
   누르면 `Y.Text`의 `[ ]`↔`[x]`만 바뀐다.
3. **네이티브 뷰 삽입.** `<DatabaseView … />` 블록 하나가 텍스트 흐름 안에 네이티브
   뷰로 그려진다. 커서는 그 블록을 한 단위로 건너뛰고, 주변을 편집해도 블록의
   원문 바이트가 바뀌지 않는다. 뷰 안 스크롤이 바깥 스크롤과 충돌하지 않는다.
4. **accordion 접기.** 접으면 본문 범위가 화면에서 사라지고, 펼치면 돌아온다.
   접기는 화면 상태일 뿐이라 `Y.Text`가 바뀌지 않는다. 접힌 상태에서 원격 편집이
   들어와도 텍스트가 어긋나지 않는다.
5. **입력 성능.** 5,000줄 문서에서 키 입력 한 번의 처리(동기화 반영 + 레이아웃)가
   16ms 안에 끝난다. 측정값을 보고서에 적는다.
6. **보고서.** 항목별 성립 여부, 측정값, Swift용 yrs 바인딩 선택(SwiftYrs 채택 또는
   자체 UniFFI 바인딩)과 그 근거, 다음 단계에서 설계를 바꿔야 할 지점.

## 영향 범위

- 새 코드: 저장소 안의 Swift 스파이크 앱(위치는 spec에서 정한다).
- 서버·웹 앱·core: 변경 없음. 로컬 모드 서버(`bun run dev`)에 접속만 한다.
- 결정 권한: Dennis Park.

## 제약

- 서버, 웹 앱, core 코드를 바꾸지 않는다. 서버 변경이 필요하다는 결론이 나면
  보고서에 적고 이번에는 고치지 않는다.
- 공개 저장소 규칙을 지킨다 — 비밀값, 로컬 경로, 디버그 산출물을 커밋하지 않는다.
- 스파이크 코드는 제품 코드로 쓰지 않는다. 결과를 보고 다시 작성한다.

## 범위 밖

- SynapseNote Markdown 문법 전체 파서, TS 파서와의 비교 테스트 체계(다음 intent).
- 표 편집, 데이터베이스 뷰의 실제 데이터 표시(자리 표시 뷰로 대신한다).
- 원격 서버 접속과 인증, 오프라인 저장, 앱 셸(사이드바·탐색·설정).
- 서버측 에이전트(마일스톤 3), `codex/server-remote-access` 병합.

## 열린 질문

1. **스파이크 플랫폼.** AppKit(`NSTextView`)과 UIKit(`UITextView`)은 TextKit 2
   동작이 다르다. 스파이크를 어디서 돌리는가.
   → **iPadOS UIKit.** iPad와 iPhone이 같은 텍스트 뷰를 쓴다. macOS를 AppKit으로
   따로 둘지 Catalyst로 합칠지는 결과를 보고 정한다.
2. **성능 목표.** 5,000줄·16ms가 적절한가.
   → **그대로 간다.**
