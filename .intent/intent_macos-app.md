# macOS 앱 첫 판 — 문서 목록, 편집, 오프라인, 에이전트

## 문제

SynapseNote를 Craft 수준의 Apple 네이티브 앱으로 옮기기로 했고, macOS 앱을 먼저 만든 뒤
iOS·iPadOS로 넓힌다. 지금 네이티브 코드는 스파이크(`codex/native-editor-spike`)뿐이다.

- 스파이크는 UIKit iOS 앱이다. 맥에서는 Catalyst로만 돌고, 메뉴·창·키보드 동작이 iPad 앱이다.
- 문서 하나만 연다. 문서 목록, 새 문서, 문서 전환이 없다.
- 문서를 기기에 저장하지 않는다. 열 때마다 서버에서 전체를 받고, 서버가 없으면 아무것도 못 한다.
- 에이전트 채팅은 Electron 데스크톱 앱의 메인 프로세스(`packages/desktop/src/main/cli-chat-command.ts`)에서만
  돈다. 서버에는 에이전트 대화를 실행하고 스트리밍하는 API가 없다(서버의 handoff API는 `claude://`·`codex://`
  URL로 외부 앱을 여는 것뿐이다). 그래서 네이티브 앱은 에이전트를 쓸 수 없다.
- 스파이크 코드는 설계 확인용이라 제품 코드로 그대로 쓰지 않기로 했다(스파이크 보고서 "한계").

## 원하는 결과

1. 맥에 설치하는 macOS 앱(SwiftUI 앱 구조, 편집기는 AppKit `NSTextView` TextKit 2)이 있다. Catalyst가 아니다.
2. 사이드바에 서버의 폴더·문서 목록이 보이고, 문서를 골라 열고, 새 문서를 만들 수 있다.
3. 편집기는 Markdown 원문을 라이브 프리뷰로 보여 준다. 커서가 있는 문단에서만 기호가 보인다.
   입력은 `Y.Text('source')`로 서버에 가고, 웹 앱과 에이전트의 편집이 앱에 실시간으로 반영된다.
4. 한 번 연 문서는 다음부터 서버 연결 없이 바로 열린다. 오프라인에서 편집하고, 다시 연결되면
   편집이 서버로 가서 그동안의 다른 편집과 합쳐진다. 편집이 사라지지 않는다.
5. 앱 안의 채팅 패널에서 Claude Code·Codex 에이전트에게 현재 문서를 문맥으로 요청하고, 응답이
   스트리밍되고, 중단할 수 있다. 에이전트가 문서를 고치면 편집기에 바로 보인다.
6. 오프라인일 때 서버가 필요한 기능(새 문서, 에이전트)은 쓸 수 없다고 화면에 표시한다.
7. 메뉴 막대와 키보드 단축키(새 문서, 실행 취소·다시 실행, 찾기, 채팅 패널 열기)가 macOS 앱의 기본 동작을 따른다.

## 영향 범위

- 새 macOS 앱 코드와 Swift·Rust(yrs 바인딩) 공유 모듈. 나중에 iOS 앱이 같은 모듈을 쓴다.
- 서버: 에이전트를 서버에서 실행해 앱에 스트리밍하는 API가 새로 필요하다. 문서 목록·생성 API는 있는 것을 쓴다.
- 웹 앱·Electron 앱: 동작을 바꾸지 않는다.
- 사용자: 운영자 한 명. 결정 권한: Dennis Park.

## 제약

- 스파이크 결론을 따른다. `Y.Text('source')`만 동기화하고, yrs 0.28 위 자체 UniFFI 바인딩을 쓴다.
- 연속 텍스트 편집기다. 블록 편집기로 만들지 않는다.
- 에이전트는 서버에서 공식 CLI(`claude`, `codex`) 바이너리로 실행한다. 앱이 Claude 구독 OAuth를 직접 쓰지 않는다.
- 기기 사본은 앱 샌드박스 안에만 둔다. 원본은 서버이고, 합칠 때 CRDT 규칙을 따른다.
- 공개 저장소에 비밀값·로컬 경로를 넣지 않는다. 앱은 저장소를 받은 사람이 빌드할 수 있어야 한다.

## 범위 밖

- iOS·iPadOS 앱(공유 모듈은 iOS에서 쓸 수 있게 만들되 앱은 만들지 않는다).
- 원격 서버(synapse.lawdigest.kr) 로그인. 이번에는 맥의 로컬 서버에 붙는다.
- 데이터베이스 뷰의 실제 데이터 표시, 검색, 그래프, 메모, 첨부 업로드.
- 오프라인 새 문서 만들기, 오프라인 검색, 오프라인 에이전트.
- 세 작성자 동시 편집 중복(`codex/concurrent-edit-duplication`), 긴 문서 부하(`codex/large-doc-concurrent-load`) 수정.
- App Store 배포, 공증.

`codex/native-local-store`의 draft intent(기기 저장)는 이 intent의 결과 4로 흡수한다.

## 열린 질문

1. **단계 나누기.** 결과 1~7을 한 번에 하지 않고 단계로 나눈다. 앱 골격과 편집기 → 문서 목록 →
   오프라인 저장 → 서버 에이전트 API와 채팅 패널 순서를 spec에서 제안한다.
2. **서버 에이전트 API의 모양.** 기존 Electron 채팅 경로(`cli-chat-command.ts`)를 서버로 옮길지, 새로 만들지는
   spec에서 코드를 조사해 정한다.
3. **편집기 파서.** 스파이크 스캐너를 다시 쓸지, core의 TS 파서와 결과를 비교하는 Swift 파서를 만들지 spec에서 정한다.
