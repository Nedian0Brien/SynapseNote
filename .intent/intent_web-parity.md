# 웹에서도 로컬과 같은 제품이 되게 한다

## 문제

`https://synapse.lawdigest.kr`에 로그인하면 사이드바에
"Couldn't load conflicts — reload to retry"가 뜬다. 그건 증상 하나고, 조사해 보니
같은 원인으로 **14개 엔드포인트가 원격 브라우저에 403을 반환한다.**

원격 모드 서버를 띄우고 배포판 브라우저와 같은 헤더로 전수 호출한 결과다:

| 기능 | 경로 | 원격 브라우저 |
|---|---|---|
| 동기화 상태·충돌 목록 | `sync/status`, `sync/conflicts` | 403 |
| 동기화 실행·충돌 해결 | `sync/trigger`, `sync/resolve-conflict`, `sync/conflict-content` | 403 |
| GitHub 계정 연결 | `local-op/auth/{status,repos,login,signout,set-identity}` | 403 |
| 프로젝트 생성·복제 | `local-op/clone`, `local-op/ok-init` | 403 |
| 스타터 팩 | `seed/{packs,plan,apply}` | 403 |
| 스킬 설치 | `skill/install-state` | 403 |
| 에디터로 열기 | `handoff`, `spawn-cursor` | 403 |
| 진단 로그 | `client-logs` | 403 |

전부 `checkLocalOpSecurity` 게이트다. 문서 편집·검색·데이터베이스 같은 핵심은
정상이지만, 그 주변이 전부 죽어 있다.

### 게이트가 지금 거꾸로 걸려 있다

게이트는 두 검사다 — 소켓 피어가 루프백인가, Origin이 루프백인가.

배포판에서 **소켓 검사는 항상 통과한다.** nginx가 앞에 있으니 피어는 언제나
127.0.0.1이다. `isLoopbackRequest`는 `req.socket.remoteAddress`만 보고
`X-Forwarded-For`를 보지 않는다. 그래서 실제로 막고 있는 건 Origin 검사뿐이고,
Origin은 **없으면 통과한다**(`hasValidLocalOpOrigin`은 헤더 부재를 허용).

같은 서버, 같은 토큰, Origin 헤더 유무만 다르게 호출한 결과:

```
POST /api/local-op/auth/status   Origin 있음: 403  │ Origin 없음: 200
POST /api/sync/trigger           Origin 있음: 403  │ Origin 없음: 202  (실제로 동기화가 돌았다)
```

정직하게 Origin을 보내는 브라우저는 막히고, 헤더를 빼는 스크립트는 통과한다.
액세스 토큰을 가진 아무 클라이언트나 지금 이 순간 원격에서 `sync/trigger`를
돌리고 GitHub 연결 상태를 읽을 수 있다. "루프백 전용"이라는 이름이 배포된
구성에서는 지키지 못하는 약속이다.

이건 이번 로그인 작업이 만든 문제가 아니다. 게이트는 2026-06-03 최초 임포트부터
있었고, 원격 접근 모드가 생기면서 처음으로 도달 가능한 조합이 됐다.

## 원하는 결과

원격 웹에서 로그인한 운영자가 데스크톱 앱과 같은 것을 할 수 있다. 구체적으로:

1. **동기화가 보이고 돌아간다.** 충돌 목록이 뜨고, sync 배지가 실제 상태를
   표시하고, 수동 동기화가 돌고, 충돌을 해결할 수 있다.
2. **프로젝트를 준비할 수 있다.** 스타터 팩 적용, 스킬 설치가 웹에서 된다.
3. **GitHub 연결을 관리할 수 있다.** 설정 → 계정에서 연결 상태를 보고 연결·해제한다.
4. **원격에서 의미 없는 기능은 그렇다고 말한다.** "에디터로 열기"는 서버 머신에서
   프로세스를 띄우는 동작이라 원격에서 성립하지 않는다. 403으로 실패하는 버튼을
   남기지 않고, 아예 감추거나 왜 없는지 적는다.
5. **게이트가 이름대로 동작한다.** 자격증명 없는 호출은 401. Origin 헤더를 빼는
   것으로 통과하는 경로가 없다.

로컬 모드는 한 글자도 달라지지 않는다. 데스크톱 앱과 `bun run dev`가 지금 쓰는
경로다.

## 영향 범위

- **사용자**: 원격 웹으로 접속하는 운영자. 데스크톱 사용자는 동작 변화 없음.
- **서버**: `local-op-security.ts`의 게이트 정의, `api-extension.ts`의 14개 핸들러
  게이트, 원격 정책에서의 admission 경로.
- **앱**: 원격에서 성립하지 않는 기능의 UI 처리(충돌 해결 버튼, 에디터로 열기,
  프로젝트 전환 등).
- **문서**: `deploy/README.md`의 "Not covered here".
- **결정 권한**: 사용자.

## 제약

- **보안 경계를 옮기는 변경이다.** 게이트를 넓히다 실수하면 원격 호출자가 운영자의
  GitHub 자격증명으로 git을 돌리게 된다. 지금도 토큰만 있으면 되는 상태지만, 그건
  고쳐야 할 결함이지 따라야 할 선례가 아니다.
- 로컬 모드 동작 불변. 데스크톱 앱은 이 서버를 그대로 쓴다.
- 원격 모드에서 자격증명 없는 접근은 계속 막혀야 한다.
- 기존 테스트와 공개 시그니처를 깨지 않는다.

## 범위 밖

- **서버측 에이전트(마일스톤 3).** Claude/Codex 채팅은 컨테이너에 CLI 바이너리도
  자격증명도 없어서 못 돈다. PTY를 서버에서 띄우는 것은 별도 마일스톤이고, 이번
  intent가 다루는 "게이트 때문에 막힌 것"과 원인이 다르다. 다만 웹에서 그 기능이
  왜 없는지 화면에 적는 것까지는 이번 범위에 넣는다.
- **다중 사용자.** 서버는 계정 하나를 갖는다. 공유·권한·초대는 다른 이야기다.
- **오프라인 동작.** 웹은 서버가 있어야 한다.
- ChatGPT 커넥터 연결. 서버는 준비됐고 붙이는 것은 사용자 몫이다.

## 답이 나온 질문

1. **`local-op/clone`과 `ok-init`을 원격에서 열어야 하나?**
   → **열지 않는다.** 원격은 워크스페이스 하나를 보는 창이고, 프로젝트 관리는
   데스크톱에서 한다. 컨테이너는 `/workspace` 하나를 서비스하므로 원격에서
   다른 프로젝트를 복제하는 것은 의미가 없다.

2. **GitHub 기기 흐름을 원격에서 열어야 하나?**
   → **읽기만 연다.** `status`와 `repos`는 원격에서 되고, `login`·`signout`·
   `set-identity`는 데스크톱 전용으로 남는다. 이 서버의 GitHub 자격증명을
   원격에서 교체할 수 있게 만들지 않는다.

3. **한 번에 다 할 것인가, 쪼갤 것인가?**
   → **쪼개되 완주한다.** 아래 단계는 순서일 뿐 범위 축소가 아니다. 단계가
   끝날 때마다 다음으로 넘어가고, 마지막 단계까지 간다.

## 단계

범위를 잃지 않도록 여기 적어 둔다. 각 단계는 자기 plan과 커밋을 갖는다.

| 단계 | 내용 | 상태 |
|---|---|---|
| P1 | 게이트 재설계 — `checkLocalOpSecurity`가 원격 정책에서 이름대로 동작한다 | 완료 (`bcf1491c`) |
| P2 | 동기화 — `sync/*` 5개를 원격 세션에 연다 | 완료 (`5a0074b6`) |
| P3 | 프로젝트 준비 — `seed/*` 3개, 스킬 3개, `client-logs` | 완료 (`28ac3228`) |
| P4 | GitHub 읽기 — `local-op/auth/{status,repos}` | 완료 (`1a618a81`) |
| P5 | 원격에서 성립하지 않는 것의 UI | 완료 (`a3cb52cd`) |

P5가 이 intent의 종료 조건이었다. 게이트 규칙 집계는 `never` 14곳,
`account-session` 14곳이다.

## 남은 한계

**웹에서 GitHub에 연결할 수 없다.** CLI의 토큰이 `$HOME/.ok/auth.yml`에 있고
compose가 `/home/node`를 tmpfs로 마운트한다. 그래서 게시(`share/*`)는 원격에서
닫혀 있고, 동기화도 데스크톱에서 원격을 붙여준 워크스페이스에서만 의미가 있다.
이 제약을 없애려면 `/home/node`를 볼륨으로 지속시키고 원격 GitHub 로그인을
허용해야 한다 — 비밀번호 하나가 곧 GitHub 접근이 된다는 뜻이라 별도 intent로
다룬다.

**서버측 에이전트는 여전히 마일스톤 3이다.** 이번에는 왜 없는지 화면에 적는
것까지만 했다.
