# 네이티브 앱이 문서를 기기에 두고 바로 연다

## 문제

SynapseNote의 원본은 원격 서버에 있고, 네이티브 앱(macOS·iPadOS·iOS)은 그 서버에 붙는
클라이언트가 된다. 스파이크 앱(`codex/native-editor-spike`)은 문서를 기기에 저장하지
않아서 문서를 열 때마다 서버와 연결하고 문서 전체를 받는다.

- **문서를 열 때마다 기다린다.** 연결, 인증, 문서 전체 전송이 끝나야 편집할 수 있다.
  5,000줄 문서는 237k 글자다.
- **오프라인에서 아무것도 못 한다.** 비행기, 지하철, 서버 점검 중에 노트를 읽지도
  쓰지도 못한다. 벤치마크 대상인 Craft는 네이티브 앱에서 기존 문서의 오프라인 편집을
  설정 없이 지원한다.
- **서버가 멈추면 앱도 멈춘다.** 스파이크 측정에서 서버가 큰 문서 처리로 30초간 응답하지
  않은 동안 다른 문서를 열 수 없었다.

웹 앱은 이미 문서를 IndexedDB에 저장하고(`packages/app/src/editor/provider-pool.ts`의
`IndexeddbPersistence`), 데이터베이스는 스냅샷 캐시와 변경 대기열을 둔다
(`database-offline-cache.ts`, `database-offline-mutation-queue.ts`). 네이티브 앱에는
대응하는 저장 계층이 없다.

## 원하는 결과

1. 한 번 연 문서는 다음부터 서버 연결 없이 바로 열린다. 5,000줄 문서가 앱 실행 후
   화면에 뜨기까지 500ms 이하다(서버 응답과 무관).
2. 오프라인에서 기존 문서를 편집할 수 있다. 다시 연결되면 편집이 서버로 가고, 그동안
   다른 기기·에이전트가 한 편집과 합쳐진다. 편집이 사라지지 않는다.
3. 최근에 연 문서, 즐겨찾기 문서는 백그라운드에서 최신 상태로 받아 둔다(Craft처럼
   닫힌 문서도 동기화).
4. 오프라인일 때 무엇이 안 되는지 화면에 적는다. 새 문서 만들기, 검색, 에이전트,
   데이터베이스 쿼리처럼 서버가 필요한 기능.
5. 기기 저장소가 커지면 오래 안 연 문서부터 비운다. 비운 문서는 다시 열 때 받는다.

## 영향 범위

- 네이티브 앱: 문서 저장 계층, 동기화 상태 표시, 오프라인 안내.
- 서버: 변경 없음이 목표. 재접속 시 대량 update를 받는 경로의 부하는 확인한다.
- 결정 권한: Dennis Park.

## 제약

- 원본은 서버의 `Y.Text('source')`다. 기기 사본은 캐시이고, 합칠 때 CRDT 규칙을 따른다.
- 기기 사본은 앱 샌드박스 안에만 둔다. 다른 앱이나 iCloud로 새지 않는다.
- 스파이크 결론(`Y.Text` 전용 동기화, 자체 UniFFI yrs 바인딩)을 따른다.

## 범위 밖

- 오프라인 새 문서 만들기, 오프라인 검색, 오프라인 데이터베이스 쿼리.
- 서버 없이 쓰는 로컬 전용 모드.
- 네이티브 앱 셸 전체(사이드바, 탐색). 이 intent는 문서 저장과 동기화만 다룬다.

## 열린 질문

1. **선행 조건.** 네이티브 앱 프로젝트(스파이크를 대체할 제품 코드)가 아직 없다. 이
   intent를 앱 기반 작업보다 먼저 할 것인가, 앱 기반 작업의 한 단계로 넣을 것인가.
2. **오프라인 데이터베이스.** 데이터베이스 레코드도 읽기 전용으로 기기에 둘 것인가.
3. **Mac.** macOS 앱을 AppKit으로 따로 만들지 Catalyst로 합칠지가 저장 계층 위치에
   영향을 주지는 않지만, 백그라운드 동기화 방식(iOS 백그라운드 작업 제한)은 플랫폼마다
   다르다. 이번에 iOS·iPadOS만 먼저 할 것인가.
