# vault 폴더 열기와 Markdown 저장

## 문제

에디터 시제품은 앱에 들어 있는 시험용 페이지만 열고, 편집 내용은 메모리에만 있다가 앱을 끄면 사라진다. 사용자가 자기 노트 폴더를 열어 쓰고 저장할 수 없으니 아직 노트 앱이 아니다.

저장 계층은 Morrow의 TS 코드(세션, 저장소, Markdown 파싱·직렬화, 저장 큐)를 수정 없이 웹 쪽에서 쓰고, Swift는 Morrow가 `VaultBridge`로 분리해 둔 파일 입출력을 맡기로 했다(2026-10-19 결정). 이렇게 하면 Morrow·Obsidian vault와의 호환, 저장 재시도, 외부 변경 시 충돌 보존, 페이지 히스토리를 그대로 이어받는다.

## 원하는 결과

- 처음 실행하면 폴더를 고르거나 새 폴더를 만드는 화면이 나온다. 고른 폴더는 다음 실행 때 다시 열린다.
- 기존 Morrow 또는 Obsidian vault를 열면 폴더 구조대로 페이지 목록이 나오고, 내용과 위키 링크, 콜아웃, 태그, frontmatter 속성이 그대로 보인다.
- 본문을 편집하면 해당 `.md` 파일에 저장된다. 저장 결과는 Morrow가 같은 편집에 대해 쓰는 파일과 바이트 단위로 같다. 편집하지 않은 파일은 다시 쓰지 않는다.
- 앱에서 새 페이지 만들기, 제목 바꾸기(파일 이름도 따라 바뀜), 페이지를 휴지통으로 보내기를 할 수 있다.
- 앱이 열려 있는 동안 다른 앱이 파일을 바꾸면 앱에 반영된다. 앱에서 저장하지 않은 편집과 겹치면 Morrow처럼 다른 쪽 내용을 페이지 히스토리에 남긴다.
- vault 안의 이미지와 첨부 파일이 에디터에 표시되고, 붙여넣거나 끌어다 놓은 이미지는 `attachments/`에 저장된다.
- 위 항목이 macOS와 iPadOS(시뮬레이터)에서 동작하고, 확인 결과가 검증 문서에 남는다.

## 영향 범위

- `feat/vault-markdown-port` 브랜치. 에디터 시제품의 시험용 페이지 목록과 메모리 저장을 대체한다.
- 결정 권한: Dennis Park

## 제약

- Morrow 파일은 수정하지 않는다(시제품과 같은 원칙).
- 사용자 폴더 밖의 파일을 읽거나 쓰지 않는다. 페이지 파일은 지우지 않고 휴지통으로 보낸다(시스템 휴지통이 없는 iOS는 vault의 `.trash/`).
- 앱 화면에는 SynapseNote 이름만 보인다.
- iCloud Drive처럼 다른 프로세스가 같은 파일을 다루는 위치에서도 파일 조정(file coordination)을 거쳐 읽고 쓴다.

## 범위 밖

- 페이지 이동(드래그 앤 드롭), 즐겨찾기, 검색, 태그·작업·그래프 화면, 페이지 히스토리 화면
- 데이터베이스·캔버스 화면, 암호화, 동기화, 가져오기·내보내기
- vault 여러 개 전환
- 첫 실행 가이드 문서 생성. Morrow 가이드는 아직 없는 기능을 설명하므로 새 vault에 넣지 않는다. 시험용 페이지 목록은 앱에서 뺀다.
- 실기기 배포

## 열린 질문

- vault 관리용 숨김 폴더 이름: Morrow 코드가 쓰는 `.morrow/`를 그대로 둘지. 제안: 그대로 둔다(Morrow vault 호환, Morrow 파일 무수정). 사용자 화면에는 보이지 않는다.
  - 답: `.morrow/` 유지 (2026-10-19, Dennis Park)
- 새 폴더 기본 위치: 제안 macOS는 `~/Documents/SynapseNote`, iOS·iPadOS는 앱의 문서 폴더(파일 앱에서 보임).
  - 답: 제안대로 (2026-10-19, Dennis Park)
