# 웹 편집기가 원문을 직접 편집한다

## 문제

한 문서가 편집 가능한 CRDT 두 개로 공유된다. 원문 `Y.Text('source')`는 네이티브 앱과 에이전트가 편집하고,
문서 트리 `Y.XmlFragment('default')`는 웹·데스크톱 편집기(Tiptap)가 편집한다. 서버가 두 CRDT를 스냅샷 비교로
다시 맞추는데(Observer A·B), 이 구조에서 세 가지 문제가 난다.

- **동시 편집이 원문을 망가뜨린다.** 서버가 원문 변경에서 파생한 서식 변경과 웹의 트리 편집이 같은 서식 경계에서
  겹치면 Yjs 병합이 서식을 엉뚱한 글자에 붙이고, 서버가 그 트리를 원문에 직렬화하면서 링크 URL 같은 내용이
  중복된다. 재현 도구(`concurrent-writers.test-helper.ts`)에서 웹이 낀 작성자 조합은 100 seed 중 8, 원문만
  편집하는 앱+에이전트 조합은 0이었다(`plan_concurrent-edit-duplication-p0.md` 결과).
- **편집하지 않은 원문 바이트가 바뀐다.** 웹 편집은 편집한 블록을 트리에서 다시 직렬화해 원문에 쓴다. `**bold*`의
  `*`가 빠지거나 앞 공백이 `&#x20;`로 바뀐다.
- **서버가 문서 크기에 비례해 일한다.** 동기화 계층(전체 직렬화, 3-way 병합, 저장 시 검사)이 5,000줄 문서에서
  편집 한 번에 수 초를 쓰는 경로를 가진다(`large-doc-concurrent-load`).

## 원하는 결과

1. 웹·데스크톱 편집기가 `Y.Text`만 편집한다. 공유 CRDT에서 `Y.XmlFragment`가 빠지고, 서버의 동기화 계층(Observer
   A·B, 저장 시 트리 검사, 3-way 병합)이 없어진다.
2. 편집 화면은 CodeMirror 6 라이브 프리뷰다. 커서가 없는 줄은 Markdown 기호를 숨기고 서식을 그려 보이며, 커서가
   있는 줄은 원문을 보인다. 네이티브 편집기(TextKit 2 라이브 프리뷰)와 같은 편집 방식이다.
3. 지금 편집기가 하는 일을 새 편집기도 한다: 제목·목록·인용·코드 블록·표·수식·Mermaid·콜아웃·이미지와 파일
   임베드·위키 링크·태그·MDX 컴포넌트·인라인 데이터베이스 표시, 슬래시 메뉴, 서식 단축키, 붙여넣기, 메모, 에이전트
   쓰기 표시, 협업 커서.
4. 사용자가 친 글자 외에는 원문이 바뀌지 않는다.
5. 세 작성자 동시 편집(재현 도구의 웹 작성자를 원문 편집으로 바꾼 1,000 seed, 실제 서버 soak)에서 중복·삭제 0.
6. 한글 입력(IME 조합)이 정상 동작하고, 조합 중에 다른 사람의 편집이 와도 조합이 깨지지 않는다.

## 영향 범위

- app: 편집기 교체. 원문 모드 `editor/SourceEditor.tsx`(이미 CodeMirror + `y-codemirror.next`로 `Y.Text`를
  편집)가 출발점이다. 공유 트리에 기대는 파일 12개(`provider-pool.ts`, `TiptapEditor.tsx`, 에이전트 쓰기 도구 등).
- server: 동기화 계층과 트리 관련 경로 제거(트리 의존 파일 16개). 에이전트 쓰기는 원문만 쓴다.
- core: 트리 의존 파일 3개. core 파서는 서버·검색·에이전트가 원문을 읽는 기준으로 남는다.
- desktop: 같은 렌더러를 쓰므로 함께 바뀐다.
- 결정 권한: Dennis Park.

## 제약

- 원본은 `Y.Text('source')`와 디스크의 Markdown 파일이다. 파일 형식은 바뀌지 않고 데이터 이전은 없다.
- 표시용 파서와 core 파서가 원문을 다르게 읽으면 core 파서가 기준이다.
- 기존 편집기를 지우기 전에 새 편집기가 3번의 기능을 갖춘다.

## 범위 밖

- 네이티브 앱.
- 새 편집 기능, 데이터베이스 기능 자체의 변경.

## 다른 intent와의 관계

- `concurrent-edit-duplication`을 대체한다. 재현 도구와 P0 측정은 이 작업의 검증에 쓴다.
- `large-doc-concurrent-load`는 동기화 계층을 없앤 뒤 다시 재서 남는 범위를 정한다.

## 열린 질문

1. **전환 방식.** 새 편집기를 설정으로 켜는 방식으로 기존 편집기와 함께 두었다가 교체할 것인가, 한 번에 교체할
   것인가.
2. **표 편집.** 표에 커서가 들어가면 원문(`| a | b |`)을 보일 것인가, 표 위젯 안에서 칸 단위로 편집할 것인가.
3. **라이브 프리뷰 규칙 공유.** 기호를 언제 숨기고 보일지를 네이티브 앱과 같은 명세 문서로 둘 것인가.
4. **성능 목표.** 5,000줄 문서에서 키 입력이 화면에 반영되기까지의 목표를 한 프레임(16ms) 이하로 둘 것인가.
