# RFC 0001: Notion database parity matrix

- Status: Active
- Last verified: 2026-07-22
- Source policy: official Notion Help Center only
- Implementation source of truth:
  [database checklist](./0001-databases-implementation-checklist.md)
- User-experience source of truth:
  [Notion UX alignment checklist](./0001-notion-ux-alignment-checklist.md)

> **UX status note:** `Complete` in this matrix currently means the underlying
> database capability is implemented. It does not mean the primary human journey
> matches Notion. User-experience parity remains open until the corresponding
> gates in the UX alignment checklist pass.

This matrix prevents “Notion-class” from becoming a vague product claim. A row
is **Done** only when its mapped checklist acceptance gates are complete across
canonical storage, validation, server/API, agent surface, UI, permissions,
offline/conflict behavior, import/export, accessibility, and tests. **Foundation**
means the canonical or query primitive exists but user-facing parity is not yet
complete. **Planned** means no parity claim.

## Maintenance protocol

1. Review the official source pages at least monthly and whenever Notion ships a
   database-related release.
2. Record the verification date and add, remove, or change rows before changing
   marketing or milestone language.
3. Map every capability or semantic delta to checklist IDs. Add missing IDs if
   the current checklist cannot express it.
4. Add acceptance fixtures for changed limits, empty/error states, permissions,
   import/export, and API behavior before setting **Done**.
5. Preserve Notion-specific behavior as an interoperability target, not a reason
   to weaken SynapseNote's file-native or agent-safety guarantees.

## Property families

The official property baseline currently includes Text, Number, Select, Status,
Multi-select, Date, Formula, Relation, Rollup, Person, Files & media, Checkbox,
URL, Email, Phone, Created time/by, Last edited time/by, Button, Unique ID, and
Place. Notion currently documents a 500-property database limit; SynapseNote
must choose and test its own explicit limit rather than inherit it accidentally.

marker. Canonical browser and agent writes remain strict.

No **Foundation** row is a user-facing parity claim. Milestone parity is granted
only when every checklist ID mapped to that row is complete and the matrix row
is explicitly changed to **Done** with dated test evidence.
