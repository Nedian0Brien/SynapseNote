The editor is where you read, write, and collaborate on your docs, and where AI agents land when they edit. WYSIWYG by default with a source-mode toggle, a frontmatter properties pane, real-time CRDT collaboration, and a file sidebar that organizes the project.

## Open a single file

Want the editor on one loose markdown file without setting up a project? Run `ok <file>`:

```bash
ok notes.md            # open a single file in the editor
ok ./specs/foo/SPEC.md # a file inside a project opens that project, focused on the doc
```

When the file is inside an existing SynapseNote project, this opens that project focused on the doc. When it's a loose file, it opens an **ephemeral single-file session**: a throwaway editor scoped to just that one file, with no project scaffolding, no agents, and no git. Your edits save straight back to the original file, and **nothing is written into the file's directory** — all session state lives in a temporary directory that's removed when you close the window. Opening a file you don't edit leaves it byte-for-byte unchanged.

It opens in the desktop app when it's installed, and falls back to your browser otherwise (press Ctrl-C in the terminal to end a browser session). Single-file sessions show just the file and the editor — no sidebar, tabs, or project switcher. Discover it any time with `ok --help`.

## Document body

Open any doc from the sidebar. The body renders as WYSIWYG markdown with familiar conventions: bold / italic / headings / lists / tables / code fences / links / images. Toggle to source mode from the editor controls to edit the raw markdown directly; both views are bound to the same CRDT document, so they stay in sync across users and AI agents.

A slash command (`/`) opens an insert menu for headings, lists, tables, code blocks, callouts, footnotes, inline math, and the other content shapes the editor supports.

### Tables

Insert a table from the slash menu. The header row stays visible as you scroll down a long table, the first column stays pinned as you scroll sideways, and dragging a row or column handle reorders it. Cells are single-line in the stored markdown: pressing Enter inside a cell — or pasting a table whose cells hold lists or paragraphs — joins the lines with `<br />`, the GFM line-break idiom, so the table stays valid for everyone else opening the file. `<br>` tags in existing files render as real line breaks and round-trip byte-for-byte.

### Mermaid diagrams

A `mermaid` code fence renders as a live diagram (the slash menu can insert one). On-diagram buttons pan, zoom, and reset the view; mouse-wheel zooming and drag panning are disabled so a large diagram never moves while you scroll past it.

### Live HTML embeds

An `html preview` code fence renders its contents live in a sandboxed iframe instead of showing the source. The slash menu's `/embed` group inserts starters — a blank theme-aware page, a chart, stat cards, custom SVG, an interactive control — that open straight into the preview.

### Find and replace

`Cmd+F` opens find in the visual editor; `Cmd+Option+F` (`Ctrl+H` on Windows / Linux) adds the replace controls. `Cmd+G` and `Shift+Cmd+G` step through matches.

## Links

Links work the way they do in the editors you already know:

- **Type a URL, then press space or enter.** A full URL (`https://…`, `www.…`, or an email address) becomes a link when you press space or enter after it. Plain words and filenames like `AGENTS.md` are left alone, and one `Cmd+Z` turns a conversion back into plain text.
- **Paste or drag in a URL.** Pasted (or dropped) on its own, it becomes a link. Pasted over selected text, it links that text instead — the text stays, the URL becomes its destination. `Cmd+Shift+V` pastes plain, with no linking.
- **Type `[text](url)`.** Closing the parenthesis converts the markdown shorthand into a real link; `Cmd+Z` restores the literal text.
- **Press `Cmd+K` with text selected.** The link popover opens with the URL field focused, pre-filled from your clipboard when it holds a URL. With the cursor inside an existing link, `Cmd+K` opens that link for editing. With no selection, `Cmd+K` keeps opening the command palette, as everywhere else.

## Right-click menu and spell check

In the desktop app, right-clicking editable text opens a native context menu. Any editable field gets **Cut / Copy / Paste / Select All**; when there's a selection or a flagged word under the cursor, **Look Up** (the macOS dictionary panel) and **Search with Google** join it.

Spell checking uses the native macOS spellchecker (language follows your macOS settings), so misspelled words get the familiar red underline. Right-clicking a flagged word adds the spelling section:

| Item | Behavior |
| --- | --- |
| *Suggestions* | The spellchecker's corrections, one row each; pick one to replace the word. |
| **Add to Dictionary** | Teaches the macOS system dictionary the word — persistent, and shared with your other Mac apps (Safari, Notes). |
| **Disable Spell Check** | Turns spell checking off app-wide. The choice persists across relaunches. |

While spell check is off, right-clicking any editable text offers **Enable Spell Check**, and the menu bar carries the same toggle as **Edit ▸ Check Spelling While Typing** (see [Edit menu](#edit-menu)) — flip either to bring the squiggles back.

Surfaces with their own specialized right-click menus — asset and wiki-link chips, the [file sidebar](#right-click-context-menus), editor tabs — keep them; the editor menu never doubles up on top. In the web build the browser's own context menu fills this role.

## Ask AI

An **Ask AI** composer is docked at the bottom of the editor — in the desktop app and in a regular browser — whenever a doc or folder view is open. It's a slim, single-line entry field that expands as you type to accept a fuller prompt (and `@`-mentions); in the desktop app, `Cmd+L` opens and focuses it. Type an instruction — "condense this doc", "research X", "make a spec from this user story" — and press Enter to hand it to an agent. `Shift+Enter` inserts a newline; the field clears once the prompt is sent.

It's the primary in-editor way to hand work to an agent, and the freetext companion to the menu-driven [Open with AI](#open-with-ai) (whole file / folder / project). Submitting dispatches the typed prompt to your **default agent** — the first one installed, in Claude → Codex → OpenCode → Cursor → Pi order — scoped to the current doc (or, in a folder view, the folder), which the agent receives as an `@`-mention. The agent picker beside the field overrides the default per send — the installed desktop agent apps plus, in the desktop app, the Terminal CLIs (Claude, Codex, OpenCode, Cursor, Pi) — and your choice is remembered on that machine. Success and failure use the same handoff toast as Open with AI.

The composer stays out of the way where it doesn't belong: it's hidden inside an AI editor's embedded view, while the [docked terminal](#terminal) is open (the terminal is its own AI entry point), and when no doc or folder is open (the empty state already offers project handoff). It's also dismissible — an **Ask AI** badge in the status bar brings it back.

### From a text selection

Select text in the WYSIWYG editor and the selection bubble menu shows an **Ask AI** button (Sparkles icon) alongside the formatting controls. Clicking it — or pressing `Cmd+Shift+I` (macOS only; that chord is the DevTools shortcut elsewhere) — opens and focuses the bottom Ask AI composer with the selected passage pinned as a removable context pill, so the exact text rides along as context. Type your instruction, pick an agent, and send. While the docked terminal is open, the button sends the selection into the active shell session instead. (Selecting an image or other non-text node doesn't show the affordance.)

### From a code block

Hovering a code block reveals a toolbar above it with its own **Ask AI** button (Sparkles icon). Clicking it sends the whole fenced block — info string and body — into the docked terminal's active shell session; with no terminal open, it opens and focuses the bottom Ask AI composer.

## Terminal

The desktop app has a built-in terminal: real login shells, docked in the editor window. Toggle it with `Cmd+J`, **View ▸ Show / Hide Terminal**, or the edge **Show terminal** tab that sits where you last closed it. It opens as a right-side column by default; buttons in its tab strip move it between the right column and the bottom dock or collapse it (sessions keep running), and the dock position is remembered.

The terminal is also the editor's AI-chat surface: the **Show terminal** tab starts your default CLI when no session is open, and the tab strip's **New chat** split button opens another CLI tab — its dropdown switches CLI (the pick sticks, shared with the Ask AI composer) or opens a plain shell tab. With text selected in the editor, `Cmd+J` stages the passage into the active CLI's input (or opens a new CLI tab when none is running) instead of toggling, and `Cmd+Shift+J` always stages it into a new CLI tab — the passage sits in the input for you to add to, and nothing is submitted until you press Enter. **Terminal ▸ New Terminal Window** (see [Terminal menu](#terminal-menu)) opens a dedicated window with the same multi-session tabs, `Cmd+<number>` tab switching, and shells starting at the project root.

Rename a tab by double-clicking it or pressing `F2`; the name you set pins over whatever title the running program reports, and clearing it falls back to that title. Reorder tabs by dragging, or move the active tab with `Cmd+Shift+←` / `Cmd+Shift+→` — untitled tabs keep a number that stays with their session as the strip is rearranged.

The shells run at full user privilege. To turn the terminal off for a project on this machine, use **Settings ▸ Terminal** or set `terminal.enabled: false` in `.ok/local/config.yml` (see the [configuration reference](/docs/reference/configuration)); the setting is project-local, never shared via git or sync, and not agent-settable — only a human can flip it.

## Properties

Every doc can carry a bit of structured information at the top: a `status`, an `owner`, a `tags` list, a date. SynapseNote calls these its **properties**.

In the raw markdown file, these properties live in a fenced block at the very top of the file, between two `---` lines. Markdown tools call that block *frontmatter*: it's just a small chunk of YAML, the doc's "labels." You never have to write it by hand: the **Properties** panel on the right of the editor shows each field as an ordinary form input (text, number, checkbox, date, or list) and saves your changes back into the file. For ordinary documents, edit the panel or the raw block in source mode and changes propagate live either way. For a database-owned record, Source Mode keeps the body editable but protects its frontmatter; edit those properties through the page property controls or Table View so the same reviewed, revision-safe database command used by agents is applied. The Markdown file remains externally editable and any outside changes are validated when SynapseNote ingests them.

A folder can describe itself (its own properties, just like a doc's) and offer templates that give new docs their starting properties. See [Folders and templates](/docs/advanced/folders-and-templates#folder-properties) for how that works.

## File sidebar

The sidebar lists every file in your project on disk, including files excluded by `.gitignore` / `.okignore`, except dot-prefixed entries and tooling internals (`.git/`, `.ok/`, `node_modules/`). Turn on **Show Hidden Files** to reveal the dot-prefixed entries. Folder rows expand and collapse; file rows open in a tab on click. The toolbar at the top of the sidebar has buttons to create files, create folders, and search.

### Right-click context menus

Right-click anywhere in the sidebar to get a context-aware menu. Three shapes share consistent ordering so the muscle memory carries across surfaces:

| Item | Empty space | Folder row | File row |
| --- | --- | --- | --- |
| New File | yes | yes | no |
| New from template | yes | yes | no |
| New Folder | yes | yes | no |
| Reveal in Finder | yes (project root) | yes | yes |
| Open with AI ▸ | yes (project scope) | yes (folder scope) | yes (file scope) |
| Share | yes (project root) | yes | yes |
| Copy full path / Copy Path ▸ | yes (full path of project root) | yes (Full / Relative) | yes (Full / Relative) |
| Show Hidden Files | yes | yes | no |
| Expand all / Collapse all | yes (tree-scoped) | yes (subtree-scoped) | no |
| Duplicate | no | yes | yes |
| Rename | no | yes | yes |
| Hide folder / Hide this file | no | yes | yes |
| Delete | no | yes | yes |

Items that depend on the desktop app (Reveal in Finder, Delete via Trash) are hidden in the web build. Asset rows (images, PDFs, other non-markdown files) suppress Open with AI, Share, Duplicate, and Hide; they keep Reveal, Copy Path, Rename, and Delete.

Expand all and Collapse all only appear when they have work to do: Expand all is hidden when no folder is collapsed; Collapse all is hidden when no folder is expanded. New from template appears only when templates are available for the target folder, and Share only when the project has a GitHub remote.

### Creating files and folders

Pick **New File**, **New from template**, or **New Folder** from any of the three menus. The sidebar shows an inline rename field at the target location; type a name and press Enter. **New from template** opens the [template picker](/docs/advanced/folders-and-templates#templates) (the same dialog the toolbar's create buttons use) and respects the folder's `templates_available` cascade.

Right-click on empty space drops the new item at the project root. Right-click on a folder drops it inside that folder.

### Hiding files and folders

**Hide this file** on a file row, or **Hide folder** on a folder row, appends a matching pattern to `.okignore`. See [Ignore patterns](/docs/features/ignore-patterns) for the full pattern syntax. The item disappears from the tree, search, and the agent's MCP tools immediately; nothing is deleted on disk.

### Show Hidden Files

The sidebar always lists every file on disk under the content directory (including files excluded by `.gitignore` / `.okignore`), except synthetic system docs. A single **Show Hidden Files** toggle on the empty-space and folder menus controls whether dot-prefixed entries are shown. It persists per-project per-machine in `.ok/local/config.yml` under `appearance.sidebar`, and also lives in the macOS **View** menu.

| Toggle | Effect |
| --- | --- |
| **Show Hidden Files** | Off by default. When on, stops the client from hiding paths that start with `.` (recovers allowed dotfiles like `brain/.archived/note.md`). Tooling internals (`.git/`, `.ok/`, `node_modules/`) stay hidden in every mode. |

On very large trees the disk walk is capped per level, and the sidebar shows a notice telling you the list is partial.

### Deleting via Trash

**Delete** moves the item to the system Trash via the same `shell.trashItem` call VS Code and Finder use: recoverable, not destructive.

### Open with AI

**Open with AI ▸** dispatches the project, the folder, or the file to one of your installed agents. The agent receives a short text prompt asking it to open the target in the SynapseNote web preview, then grounds the rest of the conversation via the [SynapseNote MCP](/docs/reference/mcp). Three scopes, three prompt shapes:

| Scope | Triggered from | Prompt template |
| --- | --- | --- |
| Project | Empty-space menu (no doc / folder active) | `Let's work on this project using SynapseNote. Open the OK editor in web view.` |
| Folder | Folder row menu (folder view active) | ``Let's work on the `<folder>` folder using SynapseNote. Open the OK editor in web view.`` |
| File | File row menu (doc active) | ``Let's work on `<path>` using SynapseNote. Open the OK editor in web view.`` |

The trailing `Open the OK editor in web view.` directive is dropped when the [`appearance.preview.autoOpen`](/docs/reference/configuration) preference is off, so the receiving agent honors the same "leave my preview alone" choice on its first turn; only the `Let's work on … using SynapseNote.` opener is sent.

To send your own freetext instruction along with the handoff, use the bottom [Ask AI](#ask-ai) composer (or the empty-state create composer on a fresh project) rather than these one-click submenus.

**Install detection** filters the submenu to just the agents you have. The desktop app probes locally; the web build asks the server (`GET /api/installed-agents`), so the answer reflects the machine the server runs on — exact on `localhost`, while against a remote server (a hosted preview, SSH tunnel, remote dev) it's the server's installs that count. When nothing is detected, the submenu shows a disabled "No installed agents found" row.

See the [per-integration pages](/docs/integrations/claude-code) for what each agent receives once dispatched.

The menu is organized into two sections. **Terminal** (desktop app only) leads: a row for each agent CLI — **Claude**, **Codex**, **OpenCode**, **Cursor**, and **Pi** — that runs the corresponding CLI (`claude`, `codex`, `opencode`, `pi`; Cursor's is `cursor-agent`) in SynapseNote's [docked terminal](#terminal) with the same scoped prompt. **Desktop** follows, listing the installed agent apps (Claude, Codex, Cursor); selecting one launches it via its deep link. Because both sections can list the same name, a Terminal **Claude** (the CLI) and a Desktop **Claude** (the app) can appear together; screen readers tell them apart by the Terminal row's "Claude CLI" accessible name. Each section renders only when it has something to launch, so on the web build — which has no docked terminal — the Terminal section is absent and a CLI pick falls back to the first installed Desktop app target.

The empty-state create composer on a fresh project carries the same Desktop / Terminal split: its Desktop rows pick the default agent the **Create** button uses, while its Terminal rows (desktop only, disabled until the workspace resolves) launch any of the five CLIs with the brief you typed.

When Claude or Codex launches from the docked terminal, SynapseNote auto-approves its own MCP tools, so the agent searches, reads, and edits the knowledge base without a per-call approval prompt. Claude additionally auto-approves the `ok open` command. OpenCode, Cursor, and Pi launch unchanged.

Nine tools stay gated: `delete` and `move` (knowledge-base-wide blast radius), `share_link` (publishes content), `install` (writes executable skill scripts into the agent's own config directory), `data_commit` and `data_undo` (canonical database transactions), `data_repair` and `data_task` (repair or durable bulk work), and `data_place_search` (sends one explicitly approved address query to a configured geocoder). For Claude, everything outside SynapseNote still prompts too, including shell commands and non-OK file edits. The guarantee is best-effort per agent: Claude uses an explicit allow/deny list, while Codex uses its own **approve** mode (auto-approve except potentially-unsafe actions) and only gets it once its SynapseNote entry is already configured, so run `ok init` for Codex if it keeps asking.

Turn it off in **Settings → Terminal → “Let agents use SynapseNote without asking”** ([`agents.autoApproveOkTools`](/docs/reference/configuration)). It applies to every project on this machine and defaults on.

## Command palette

`Cmd+K` opens the command palette in both the desktop app and the browser. Type to jump to any file or folder, run create commands, open the graph or settings, or dispatch to an agent; recently opened entries surface first. In the desktop app it also switches projects and worktrees.

Choose **Open Agent Runs** to inspect database work proposed or executed by agents. The panel first loads a compact history, then fetches the exact intent, stable-ID scope, proposed and actual diffs, verification, failure, and undo capability only for the selected run. Raw prompts are not stored. Active runs refresh automatically, and proposals too large for exact local history show an explicit size-limit notice rather than silent truncation.

Choose **Open databases** to browse canonical Markdown records in a snapshot-consistent table. The row open action navigates to that same Markdown file as a normal SynapseNote page; it does not create a database-only copy. On that page, the H1 shows the source's canonical Title property instead of the storage filename. Editing the H1 or a supported database-owned property obtains the record by stable ID, binds the current revision to an exact plan, asks for approval, and uses the same verified transaction engine as Table and agent writes; changing Title never renames the file or changes its stable identity. Duplicate freezes the source record revision and asks the server to copy its complete values and Markdown body under a new stable ID; the copy remains a ghost row until approval. Archive is an exact `_sn.archived_at` state transition that keeps the file path and stable ID intact. Archived rows are absent from normal queries and lexical search; **Show archived** explicitly includes them and exposes Restore. Move preserves the stable record ID and body while atomically deleting the old source path and creating the target source path. Only explicitly mapped compatible properties and options move; missing required mappings, occupied targets, and intervening edits fail closed. Title, text, number, checkbox, select, multi-select, URL, email, phone, and date cells expose the first inline editing path. Select loaded rows to plan one revision-bound property change across up to 100 records; every affected cell remains a ghost until the exact multi-file transaction commits. **New record** plans a titled Markdown record and shows it as a ghost row before creation. The row action can also plan an exact revision-bound deletion; the record remains visible as a **Proposed deletion** ghost until approval. Saving a cell, applying a bulk edit, creating, duplicating, moving, archiving/restoring, or deleting a row creates an exact plan and renders the proposed result as a dashed **Proposed · not saved** ghost; it is not canonical and no commit is sent until you approve the visible plan. After commit and verification, the table reloads the canonical snapshot. Discarding or failing the plan removes the ghost without changing the Markdown record. **Undo last change** first verifies that the canonical snapshot and paths remain conflict-free, then atomically restores every affected Markdown file. Record changes refresh the selected database automatically, while schema, view, Git, and branch changes refresh the workspace catalog and table without a page reload.

Choose **Create database** to start from a blank Title-and-Table schema, a reviewed Tasks/Content calendar/CRM starter schema, an existing content-relative folder, or a CSV/TSV file of up to 100 records. Before review, the dialog explains what one record means and shows the canonical folder, stable key, initial view, properties, and record count. Delimited imports require a non-empty first-column Title, reject duplicate or missing headers, and infer only strict numbers, booleans, and valid ISO dates; the exact generated manifest and records remain unsaved ghosts until **Commit creation**. Existing-folder creation commits only the manifest. It then opens a read-only onboarding scan that classifies paths, shows required-value or invalid-file blockers, and keeps **Start onboarding** disabled for incomplete scans or unresolved blockers. Approving a blocker-free scan launches a durable revision-bound task that assigns missing stable record IDs and refreshes the index. Agents use the same desired-state draft, immutable plan, exact approval, and task-preview contracts rather than a privileged creation path.

A database may contain several independently stored data sources; choose any source from the database list to browse its own schema and records. Cross-source compatibility is never inferred from matching display names. The shared manifest declares each allowed source→target direction and maps stable property IDs, plus stable option IDs when vocabularies differ. **Move record** appears only when the current source has at least one explicit compatible target, and the picker shows how many properties are mapped. The server revalidates the mapping, requires Title and every required target property to be covered, and applies mapped Select, Status, and Multi-select options in the same atomic move. Reverse moves require a separate reverse mapping.

Use the arrow button beside a column name to review a property-type conversion. The dialog preserves the stable property identity, previews every indexed record up to the explicit 10,000-row bound, and shows conditional failures and lossy rows before it exposes an exact plan. A single invalid row blocks the migration. Flattening structured values requires a separate loss acknowledgement and a second preview; it never rides on ordinary plan approval. Supported option conversions reuse stable option keys instead of display names. The resulting schema edit and all record rewrites commit as one verified transaction, and **Undo last change** restores both the original property schema and exact source values. The only Title property and derived, virtual, or allocated properties cannot be converted independently.

Choose a saved view above the Table to apply its canonical filter, ordered sorts, group and subgroup, projection order, and display configuration. Only properties in the saved projection become Table columns; this presentation setting does not grant or revoke read permission, and the server still applies effective property access before projection. **Filters** opens the saved-query editor for that view. Conditions use only operators valid for the selected property and can be nested in explicit AND, OR, and NOT groups; the `in` operator accepts a typed JSON array. **View settings** edits the complete ordered sort and two-level grouping lists, projection visibility and order, Markdown body projection, Table wrapping, row height, stable-property widths, and ordered conditional colors. A color rule reuses the same typed recursive filter contract and targets either the entire page/row or one property; the first matching rule for each target wins. The server evaluates colors only after record permission scope is fixed and refuses a rule whose filter or target references a denied property, so display metadata cannot leak hidden values. Saving either dialog changes the view manifest through the same ghost review and exact-plan commit used by record edits, so the current table does not silently adopt an unreviewed query or presentation. **Clear saved filters** removes only the selected view's filter and leaves its stable identity, layout, sort, groups, projection, and color rules intact. **All records** bypasses saved views without modifying them.

**Manage views** creates a Table view with a fresh stable ID and collision-free stable key, renames it without changing either identity, duplicates the complete query and presentation under a new identity, reorders views for that source, and marks favorites in the shared manifest. Deleting a view requires an explicit confirmation and ordinary plan review. The canonical default view cannot be deleted until it is changed or cleared, so a lifecycle edit cannot leave a dangling default reference.

**Make default** stores the selected stable view ID on its canonical source through exact-plan review. A default must exist and belong to that source; renames do not break the link, and deleting the referenced view is refused until the default is changed or cleared. Each browser also remembers the last view chosen for that database source. The personal choice wins over the canonical default, including an explicit **All records** choice, but it remains local UI state and never enters the shared manifest or changes another user’s default.

Choose **Templates** in a database to create reusable record starters. A database template stores typed defaults by stable property ID plus a Markdown body, and can be the default for its data source, selected saved views, or named creation entry points such as quick capture. New record creation resolves entry-point, view, and source defaults deterministically, while an explicit template always wins; **Blank record** skips the template body. Edit, duplicate, reorder, archive/restore, and delete all use the same ghost review and exact manifest plan as other schema changes. Archiving clears its defaults so a hidden template can never keep receiving new records.

Enable **Repeat this template** to create records on a daily, weekly, monthly, or anchored interval schedule. Every schedule has an explicit timezone, active owner, pause control, and bounded retry policy. Scheduled creation uses the same exact plan, verified commit, and undo journal as a reviewed manual creation; restart-safe run IDs prevent duplicate records after an uncertain response. The Templates dialog shows newest-first success, retry, and failure history. After extended downtime SynapseNote creates only the latest missed occurrence instead of producing an unbounded backlog, and it finishes a pending retry before starting a newer occurrence. Archiving an active repeating template pauses it automatically.

### Embedded and linked database views

Insert **Database view** from the slash menu to place a live saved view inside an MDX document. The block stores only the stable `databaseId`, `sourceId`, and `viewId` references plus an `inline` or `full-page` display mode; it never copies records into the document. Set those fields in the block properties, or let an agent author the equivalent canonical component:

```mdx
<DatabaseView
  databaseId="db_projects"
  sourceId="ds_tasks"
  viewId="view_active"
  mode="inline"
/>
```

Linked Table views expose the same applicable record journey as the full database: create, open, duplicate, move, archive, restore, and delete. Open navigates directly to the canonical Markdown page. Mutating actions open the full database review surface already bound to the selected stable record, so the linked view cannot bypass ghost rendering, exact-plan approval, write guards, verification, or undo. **Show archived** re-queries the same saved view with explicit archive inclusion before offering Restore.

Both modes query the latest canonical source through the referenced saved view, apply its projection and Table display settings, and refresh when that database changes. Inline mode keeps the table bounded inside the document; full-page mode expands the same renderer across the available workspace width. **Open full database** opens Table View already scoped to the referenced source and view. Renaming or reordering the saved view keeps the link intact because identity is stable; deleting the source or view produces an explicit broken-reference state instead of showing stale copied data.

Open a database record as a normal page and choose **Comments** to discuss the whole page or an eligible assigned property without modifying its Markdown body. Threads support active database-person mentions, replies, and resolve/reopen. Property comments intentionally exclude Title, Formula, Rollup, Button, and Unique ID values. Humans and agents share the same revision-safe thread artifacts; agents use `data_comments` and must pass the latest returned revision for every mutation.

Choose **Record history** on that page for a property-aware view of its durable timeline. Each entry names the stable database properties and/or page body that changed and distinguishes reviewed human/agent attribution, upstream Git sync, and external filesystem edits. It uses the same rename-aware versions as the ordinary Timeline panel, so no browser-only audit log or copied record history is created.

Choose **Relations** to open permission-visible related records by their canonical Markdown paths. Relation values stay stable record IDs in frontmatter and do not become generated wiki links, while the ordinary page Backlinks panel continues to count only links explicitly authored in Markdown. Unavailable and permission-denied relation targets share a non-disclosing count, and long relation lists state when the bounded navigation result is truncated.

Side and center peek use that same record context rather than a reduced copy: the stable query projection supplies title and properties, the canonical document supplies icon, cover, and body, and the same Comments, History, Relations, Backlinks, and **Open full page** destinations remain available. Closing a peek discards presentation state only; it does not create or fork a database page.

Within Table View, focus a cell and use the arrow keys to move through the loaded grid or Enter to edit. Hold Shift while clicking or using the arrow keys to select a rectangular range. Copy, right-click **Copy selected cells**, or drag the range to serialize the same quoted, locale-neutral TSV; dropping it on another cell follows the same path as paste. **Copy TSV** exports selected rows with headers. Paste or drop a rectangular TSV block into a focused cell to validate every destination value first and preview one atomic, revision-bound multi-record plan; invalid or out-of-range matrices do not partially apply. The cell context menu also exposes edit and applicable record actions through the same reviewed mutation commands.

Open **Table layout and calculations** to resize, reorder, or hide columns, toggle wrapping, and choose compact, standard, or tall rows. Title stays visible and frozen as the first data column. With **All records**, layout choices are stored locally per source and reconcile by stable property ID when the schema changes. An active saved view instead applies its reviewed canonical projection order and Table display configuration without overwriting that personal All records layout. A column calculation such as count, unique count, sum, average, or date range is computed by the server over the complete permission-scoped result snapshot—not just the rows currently loaded in the browser—and appears in the sticky footer. Large loaded result sets render through a windowed row viewport while preserving arrow-key navigation.

Board views use one saved group and an optional subgroup swimlane. Status, Select, Multi-select, Person, Relation, Checkbox, and observed typed values retain stable identities; option-backed and Checkbox groups can remain visible while empty. **View settings** controls projected card properties, small/medium/large cards, an optional local Files & media cover, cover fit, column color, group limits, and per-group card limits. Full-snapshot group counts stay distinct from returned-page membership metadata, so the browser can render only records it was allowed to receive while reporting explicit group truncation. Moving a card with the keyboard selector or drag and drop compiles every changed group and subgroup property into one revision-bound exact plan. Linked Board views use the same renderer and hand changes to the canonical review dialog before any Markdown is written. External image URLs are not loaded as covers automatically.

Timeline views plot either one Date property—including its canonical range—or separate start and end Date properties. The saved scale ranges from hours through years; calendar-sized steps clamp safely at month ends. Optional groups use the same permission-scoped saved grouping contract, while a same-source Relation property draws dependency connectors only when both records are present in the returned snapshot. The left table can show the first projected properties, page conditional colors apply to bars, Today remains marked, and records without a start stay in an explicit **No date** lane rather than disappearing. Keyboard buttons, whole-bar drag, and draggable start/end handles compile a move or resize into one stable-property, revision-bound exact plan. Separate start/end moves update both properties atomically. Linked Timelines use the same renderer and canonical review dialog. Layout fields needed for plotting are fetched even when visually hidden, but permission denial fails the query instead of exposing or misclassifying a date.

Calendar views map one Date property into a saved month or week range. Settings control Sunday/Monday week start, weekend visibility, an IANA timezone, and the maximum cards shown per day. Date ranges span every covered local day; cards retain projected context and conditional page colors, while records without a date remain visible as an explicit count. Dragging a card reschedules the whole range and its edge handles resize it. Date-time moves preserve wall-clock time across daylight-saving changes. Full and linked Calendars send each change through one stable-key, revision-bound exact-plan review, and a hidden mapped Date remains permission checked rather than inferred in the browser.

List views provide a compact or comfortable document-oriented layout with Title first and the ordered visible properties at the right. The first saved group can become a collapsible counted section. An optional same-source Relation forms a cycle-safe parent tree, with Up/Down row navigation, Left/Right hierarchy navigation, and Enter to open the canonical Markdown record. Page and property conditional colors remain visible. The parent Relation is fetched as a permission-checked operational field even when hidden, and full and linked Lists share the same renderer.

Gallery views display small, medium, or large visual cards using an optional Files & media property. Images can fit inside the preview or crop to fill it; Title can be hidden and the remaining visible properties retain their saved order and conditional colors. Available local images load lazily through the project asset route. SynapseNote does not automatically fetch external media: empty values, external URLs, missing files, unsupported file types, and image decode failures show explicit deterministic fallback art. Hidden preview properties remain permission checked, and full and linked Galleries use the same renderer.

Chart views render vertical or horizontal bars, lines, donuts, or one headline number from the same revision-bound aggregate query used by agents and APIs. Settings choose a typed dimension, optional series, record count or compatible property aggregation, legend, value and axis labels, group limit, and bounded drill-through row limit. Legends can hide series; grouped points expose hover values and keyboard-accessible drill-through controls. Empty results, nonpositive donut values, group truncation, and partially loaded drill-through tables stay explicit. Hidden dimension and measure properties remain permission checked, and full and linked Charts share the renderer without recomputing totals in the browser.

Form views turn writable database properties into an ordered intake flow without showing existing response rows. Settings choose internal workspace or public access, question labels and help, required answers, earlier-question conditions, close time and closed copy, confirmation copy, local upload limits, duplicate checks, rate bounds, and retention policy. The browser hides conditional questions immediately and uploads Files answers through a Form-scoped asset route; that route derives the destination from the configured source, ignores caller paths, repeats access and close checks, and has a separate bounded upload window, so a public Form does not expose the ordinary loopback-only project upload endpoint. The submission server independently checks access, visibility, required values, property types and constraints, local-only files, close time, honeypot, completion speed, rate window, and duplicate policy before writing. Accepted responses use the same exact-plan transaction path as reviewed database edits and are attributed to the stable Form view. Reusing the same submission ID with unchanged answers is safe across server restarts; changed reuse is rejected. The durable abuse ledger stores only hashed submission/rate identities and safe receipts—never answers or remote addresses. When retention is **Delete after**, an hourly revision-bound exact transaction removes due responses through the normal verification, audit, idempotency, and recovery path.

Formula and Rollup columns are read-only derived values. Use the pencil action in a computed column header to edit its definition. Formula editing provides stable-property and function suggestions, resolved reference cards, source-located validation, canonical formatting, and a frozen UTC preview; invalid formulas cannot enter review. Rollup editing limits relation, target, and aggregation choices to compatible types, then previews the unsaved candidate through the server against the current permission and index snapshot without changing the manifest or Markdown. Typed failures remain visible with their error code. Reviewed changes use the same plan and verified commit path as agent schema edits.

Created time, Last edited time, Created by, and Last edited by are also read-only columns. Creation stores one canonical timestamp and actor with the record identity and keeps them through edits and source moves; Duplicate creates a new identity attributed to the duplicating actor. Last edited metadata advances on reviewed writes and also reflects later external file edits as `filesystem · local`. Time columns behave like Date values. Actor columns expose stable `human`, `agent`, `sync`, `filesystem`, or `system` provenance and copy/export the compact `kind|principal` key. All four support typed filters and Formula references, pass through normal property permissions, and cannot be pasted, imported, edited as ordinary frontmatter properties, or assigned by an agent.

Button properties are virtual controls rather than stored record values. A click plans every configured step against the exact displayed record revision, resolves stable property/source IDs, captures the current permission-policy revisions, and shows the internal record diff plus the precise external connection, fields, body disclosure, and byte count before anything runs. Internal-only Button plans use the ordinary reviewed database commit and undo path. External webhook definitions store only a server-side connection ID—never a URL, credential, or secret—in the public database manifest. External delivery is intentionally disabled until the isolated connection executor and durable delivery history are available; when such a step is present, the review states that no internal or external action has run and keeps the Run control disabled.

Database and source headers can also expose Buttons that are not tied to a row. These Buttons are authored with stable IDs through the same desired-state plan used by agents, appear only at their declared database or source scope, and can create several records as one reviewed action. The server permission-checks every step and returns one exact atomic plan without fabricating a current record or revision. After approval, the normal verified commit and undo path applies all records together.

Unique ID properties are allocated, read-only record identifiers such as `TASK-42`. Canonical Markdown stores only the positive numeric part; the manifest stores the configurable prefix and a monotonic next-number watermark, so a standalone clone continues the sequence without a cache. New records and duplicates receive fresh numbers, ordinary edits retain them, and deleted numbers are never reused. Use the pencil beside a Unique ID column to change its prefix without rewriting record numbers. Copy and CSV/TSV export use the formatted value, while paste/import and ordinary agent mutations cannot forge one. The preview-first database repair flow assigns fresh numbers to missing, invalid, or duplicate values and advances the manifest watermark in the same approval-bound, rollback-safe transaction.

Place properties keep a name, address, latitude, longitude, precision, and source as one canonical value. Manual editing and the coordinate preview stay on-device and work offline. Choosing **Approximate area** rounds coordinates before storage, so exports, agents, and later map links cannot recover the original exact point. External address search and map links are independently disabled by default; use the pencil beside the Place column to enable either. Search requires a fresh consent checkbox before every submitted query and never sends keystrokes as autocomplete. Map display is a click-only OpenStreetMap link labeled as coordinate sharing; no remote tiles load in the table. When no operator geocoder is configured or it is offline, stored places and manual coordinate entry continue to work normally.

Map views plot up to 100 records from a selected Place property, cluster nearby pins, pan and zoom, and open the ordinary Markdown record from a pin or cluster. Records without coordinates remain available in an explicit **Missing locations** list, and a saved marker limit is never disguised as a complete result. The default **Private local map** uses an on-device coordinate grid and makes no network request. OpenStreetMap tiles can be selected only after external maps are explicitly enabled for that Place property and the saved-view change is reviewed. Provider errors visibly fall back to the local map without losing pins or interaction. Full and linked Map views use the same settings and renderer.

Dashboard views compose up to twelve existing Table, Board, Timeline, Calendar, List, Gallery, Chart, Map, or Feed saved views into persistent rows of up to four columns. Every widget keeps its own source, saved query, bounds, and permission checks. Global filters store a typed clause per applicable source, while linked selections use a declared Relation property to filter one widget from another without copying records. Row height, widget order, width, and title are saved in the reviewed manifest; database changes refresh the affected child queries and one failed widget does not erase the rest. On narrow screens the same rows stack into one column. Full and linked Dashboards share the renderer, and linked Dashboards query only their child views. Stable row, widget, filter, source, property, and view IDs also let agents inspect and edit the layout without relying on labels or browser coordinates.

Feed views show records as a linear stack of cards ordered newest-first by one saved Date, Created time, or Last edited time property. An optional Person, Created by, or Last edited by property identifies the author; otherwise the source name and canonical Markdown path keep provenance visible. Projected properties can be shown or hidden, card density is saved, and every card opens the ordinary record page. Pages are bounded to at most 100 records and continue through the same snapshot-bound cursor as other database queries, with partial counts always visible. Optional unread dots are stored only for the current app session—never synced or presented as durable view counts. Full, linked, and Dashboard Feed surfaces share this contract, so agents can create or edit the view using stable property IDs and receive the same explicit ordering, permission, and truncation semantics.

Each saved view also stores how its records open: **Side peek**, **Center peek**, or **Full page**. Change **Open records in** in the view settings and the stable shared choice applies in both full and embedded database surfaces. Gallery, Calendar, and Map default to Center peek; other saved layouts default to Side peek. **All records** has no saved-view configuration and opens the ordinary full page. Both peeks keep the database visible, load the current canonical Markdown body, show only properties already projected by the permission-scoped query, and offer **Open full page** without creating a second record copy.

On a full database record page, choose **Customize layout** to place properties in **Pinned**, **Panel**, **Hidden**, or a named group inside an ordered section. You can reorder sections and groups, start a group collapsed, and enable full-width content. The layout is stable-ID source configuration, so agents can edit it without relying on labels and every existing record uses the same reviewed default immediately. Applying a layout changes only the database manifest; it never rewrites record Markdown. Title stays in the page header, a property cannot occupy two regions, and any newly added property remains visible in Panel until you explicitly place or hide it.

Choose **Customize this record** for a narrow presentation-only exception. Each property can inherit its source placement or explicitly become Pinned, Panel, or Hidden; an existing group can inherit, start collapsed, or start expanded; and content width can inherit, become full, or return to standard. The reviewed override is stored in the record's canonical `_sn` metadata, so it survives Git, external editors, restarts, and agent access. It cannot create layout structure or change data. **Reset to source layout** removes it explicitly. Normal edits, archive/restore, and duplication preserve it, while moving to another source clears it because source-local layout IDs are not portable.

Loading and empty results are explicit. Invalid schemas, stale or failed indexes, network disconnection, canonical-write conflicts, permission denials, and other service failures are never collapsed into an empty table. Recovery actions are state-specific: reads may retry, stale writes reload the latest canonical snapshot without replaying the mutation, and permission denial waits for access instead of offering a misleading retry.

Markdown remains externally editable even when an outside tool writes a property value that no longer satisfies the database schema. SynapseNote leaves that raw value untouched on disk, keeps the rest of the record searchable, and shows the affected cell as an explicit invalid preserved value with its diagnostic. Open the cell to start from the original raw value and correct it through the normal reviewed plan. Typed filters, groups, calculations, Formula, and Rollup never coerce the invalid value or mistake it for an ordinary empty value; derived dependencies surface a typed error. Permission-hidden properties do not leak their raw value or diagnostic. Copy and CSV/TSV export encode a visible `#INVALID(code): value` marker instead of emitting an empty cell, while import and every canonical write remain strict.

URL, Email, and Phone cells validate edits before planning. Their displayed values can be opened through safe web, mail, and telephone targets or copied exactly without entering edit mode.

Number cells can display fixed or bounded precision, locale grouping, signs, percent, currency, standard units, or a custom prefix/suffix while storing and editing the same locale-neutral finite number. Display formatting does not affect filters, sorts, calculations, API values, or agent writes.

Date cells use a dedicated editor for all-day dates or precise times, an optional end, an IANA timezone, and a start- or end-anchored reminder. Invalid calendar dates, reversed or mixed-precision ranges, nonexistent daylight-saving local times, and ambiguous locale-formatted input are rejected before planning. Simple dates remain compact ISO strings; advanced values round-trip as one stable JSON/YAML object through Markdown, API, agent writes, clipboard, CSV/TSV, and JSON export. A Date property whose format style is `relative` displays relative to the current clock while retaining the same canonical value.

Person cells use the database's shared identity directory for local users, collaborators, guests, and agents. Records retain stable Person IDs while Markdown and CSV/TSV use readable keys. Table and bulk editors support one or many people, label agents and inactive identities, keep inactive historical assignments readable, and prevent an inactive identity from being newly assigned. Search can find a record by a Person display name, while query and context-pack responses include only the minimal identity cards referenced by permission-visible Person fields; runtime subject IDs and email profiles are not copied into those results.

Relation cells store stable record IDs with explicit one/many cardinality. Their picker searches up to 100 permission-visible records in the declared target source, shows readable titles without persisting those labels, keeps an unavailable existing ID removable without revealing whether it is missing or denied, and applies cell or bulk changes through the normal exact-plan review. Clipboard and CSV/TSV use one ID or a JSON ID array. Queries and token-budgeted context packs include only the minimal readable target cards referenced by returned records; deeper traversal is opt-in and bounded. A target cannot be deleted or moved to the wrong source while a surviving relation still points to it. A two-way relation is stored as two properties with symmetric stable `pairedPropertyId` references. Editing either side writes both records under one revision-bound plan, and a one-to-one replacement removes the previous inverse edge atomically. The two properties must be created, removed, or restored together; removing populated properties requires exact-revision rewrites for every affected record, while restoration never silently resurrects retired links.

Files & media cells store an ordered list of local assets and external HTTP(S) URLs with optional display names and captions. The cell editor uploads through the same protected attachment pipeline as editor drops, adds external URLs, previews supported images, opens the existing asset viewer, reorders entries, and labels a missing local file without persisting a stale missing flag. Query and context-pack responses expose only a compact `fileStates` map for permission-visible local paths. CSV/TSV interchange uses a compact JSON object array and rejects unsafe paths, credential-bearing URLs, duplicates, and malformed metadata before a plan is created.

**Export current CSV** follows a fresh snapshot of the active view scope, while **Export all CSV** uses a fresh complete source snapshot including archived records. Both stop at the explicit 10,000-row browser limit. Stable filenames end in `-current.csv` or `-all.csv`; UTF-8/CRLF files put `record_id` first and property keys in manifest order. Numbers are canonical (`1234.5`), never display-formatted (`$1,234.50`); advanced dates use stable JSON, options use stable keys, relations use stable record IDs, and ordinary empty values remain empty cells. Computed nulls use `null`, typed Formula/Rollup failures use `#ERROR(code): message`, and externally preserved invalid values use `#INVALID(code): value`, so copying or exporting never disguises a failed or untyped value as empty. **Import CSV/TSV** updates existing records addressed by `record_id` and accepts up to 100 rows. Before planning, it detects UTF-8, BOM-marked UTF-16, or Windows-1252 input and comma, tab, or semicolon delimiters. A confirmation preview shows header-to-property mappings, canonical sample rows, empty/date/option counts, and every typed-value issue. Confirmation then resolves each current record revision, validates the complete file again, and creates one atomic review plan. Formula and Rollup columns are rejected as derived read-only import targets. A localized or otherwise invalid number or date blocks planning. Creating a brand-new database from a delimited file is a separate workflow.

Person columns interchange JSON arrays of stable readable keys. Import resolves an ID, key, or unambiguous exact display name from the same database identity directory and refuses unknown, ambiguous, or inactive new assignments.

**Export JSON** writes the complete source as `<source-key>-all.json` using the versioned `synapsenote.database-export` version 1 envelope. It retains stable database, source, property, option, and record IDs; schema and snapshot revisions; canonical property-ID-keyed values; record revisions; and an explicit complete result receipt. A partial or internally inconsistent snapshot is refused rather than exported.

Multi-select cells store a set of stable option IDs and display their current names. Single-cell and bulk editors deduplicate repeated choices. TSV and CSV use stable option keys in JSON arrays, so renaming a visible label does not change the interchange identity; agent `add`/`remove` operations use the same idempotent set semantics.

**Manage Select options** previews rename, color, ordering, archive/restore, merge, and safe deletion using stable option IDs. Archived options stay visible on records that already use them but cannot be assigned by Table, clipboard/import, or agent writes. Merge and delete inspect a fresh complete source snapshot including archived records; the preview reports affected records, saved views, defaults, and blocking references before an exact server plan is created. Merge atomically updates the manifest and as many as 10,000 revision-bound records and remains undoable. Larger sources fail closed before any partial usage scan or mutation is presented as complete.

**Status** uses three workflow groups—To-do, In progress, and Complete—with stable group and option IDs. Table menus show the group for each status, while sorting and grouped query results use workflow order instead of label or ID order. Status values remain readable option keys in Markdown and become stable IDs in queries and mutations. Agents may omit the initial group configuration to receive Not started, In progress, and Done defaults; the schema exposes deterministic progress values of 0, 0.5, and 1.

For **Checkbox** columns, a bulk selection can set one shared checked state or choose **Toggle selected** to invert each record independently. The preview remains revision-bound and shows the exact per-record booleans before the normal atomic commit and undo flow.

A `tag:` prefix searches by tag: `tag:` alone lists every tag, `tag:fr` narrows the tag list, and `tag:frontend` lists the docs tagged `#frontend` (including its hierarchy children). When semantic search is configured for the project, a **By meaning** pill switches the palette to meaning-based search — press Enter to run it; typing alone never fires a query.

## Sidebars and window width

The editor has two sidebars: the file sidebar on the left and the document panel on the right (Outline, Links, Properties, Timeline). Both adapt to the window:

- At comfortable widths (1280px and up) both sidebars open by default.
- Between 1024px and 1279px the document panel defaults to collapsed so the editor keeps its breathing room; the file sidebar stays open.
- Below 1024px both default to collapsed so the editor canvas isn't squeezed off-screen.
- When SynapseNote is opened inside an AI editor's webview (Cursor, Codex, Claude Desktop), both sidebars start collapsed regardless of width; the embedded view is for reading the content you were sent, not for file management.

The defaults only apply until you toggle. SynapseNote remembers your most recent Show / Hide for each sidebar in your browser and survives reloads. When you come back to the same layout context (narrow window, comfortable window, or embedded view) you used last, your toggle is what you'll see. Toggling in a different context replaces that memory; only your most recent choice sticks, so a stale preference from a wide-monitor session can't quietly override what you just chose on a narrow screen.

Keyboard shortcuts (use `Ctrl` on Windows / Linux in place of `Cmd`, unless the shortcut already uses `Ctrl`):

| Shortcut | Action |
| --- | --- |

| `Ctrl+Tab` | Move to the next editor tab. |
| `Ctrl+Shift+Tab` | Move to the previous editor tab. |
| `Cmd+1` ... `Cmd+8` | Jump to one of the first eight editor tabs. |
| `Cmd+9` | Jump to the last editor tab. |

## Real-time collaboration

Everything in the editor (body, frontmatter, sidebar toggles) is backed by a CRDT. You and multiple AI agents writing through MCP can edit the same doc concurrently. Per-user presence is shown in the editor header; the **agent activity** view ([Agent activity](/docs/features/agent-activity)) groups every burst of agent edits with per-burst diffs and selective undo.

For recovery + history, see [Timeline and recovery](/docs/features/timeline-and-recovery).
