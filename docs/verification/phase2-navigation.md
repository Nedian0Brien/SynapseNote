## 구현 중 발견하고 고친 것

1. **macOS에서 앱이 실행 직후나 Home·페이지 이동 때 종료됨**: WebKit SwiftUI의 `WebView` 생성 단계에서 `EXC_BREAKPOINT`가 났다. 원인은 두 가지였다. 첫째, `columnVisibility`를 계산형 바인딩으로 넘기면 실행 직후 종료됐다. `@State`로 바꾸자 사라졌다. 둘째, 편집기 위에 겹친 홈·휴지통을 `NavigationStack`으로 감싸면 그 제목과 툴바가 열로 올라가면서 `WebView`가 다시 만들어지고 종료됐다. 겹치는 화면은 일반 뷰로 두고, 툴바 항목은 늘 같은 구조로 둔다. 1단계에서도 휴지통이 같은 구조였으나 macOS에서 휴지통 이동을 시험하지 않아 드러나지 않았다.
2. **팔레트 결과·탭이 손쉬운 사용의 누르기로 동작하지 않음**: `onTapGesture`를 `Button`으로 바꿨다.
3. **탭이 하나일 때 팔레트의 Close Tab이 창을 닫음**: 팔레트에서는 탭이 2개 이상일 때만 보인다. macOS File 메뉴의 ⌘W는 누른 시점에 탭이 여럿이면 탭을, 하나면 창을 닫는다.
4. **사이드바 표시가 시스템 버튼과 서로 되돌림**: 집중 모드·사이드바 명령이 바뀔 때만 표시 상태를 정한다.
5. 검색으로 연 페이지의 상위 페이지가 사이드바에서 펼쳐지지 않던 문제, iPhone에서 선택된 행을 다시 누르면 본문으로 넘어가지 않던 문제, 홈 통계 칸 줄바꿈을 고쳤다.

## 기록해 둘 동작

- 홈에서 작업을 체크하면 Morrow 직렬화기가 페이지를 다시 써서 `![[diagram.png]]`가 `![](attachments/diagram.png)`가 된다. 편집기에서 글을 고칠 때와 같은 Morrow 동작이며 이번 단계에서 바꾸지 않았다. Obsidian에서도 두 형식 모두 열린다.
- 캔버스 페이지는 열람 기록을 남기지 않는다. 캔버스의 페이지 기록을 저장하면 `.canvas` 파일을 새로 쓰기 때문에, 캔버스 화면을 만드는 5단계에서 다시 정한다.
- 시뮬레이터 자동 조작 도구로는 iPad 내비게이션 막대의 사이드바 버튼 탭이 전달되지 않았다(1단계 빌드도 같았다). 좌표로 터치를 넣는 도구로는 툴바 버튼이 동작했다.

## 사용자 확인 요청

1. macOS에서 페이지 본문을 클릭한 채 ⌘K(선택 없음 → 팔레트, 글 선택 → 링크 편집), ⇧⌘F, Esc(집중 모드 해제), ⌘T·⌘W·⌃Tab을 눌러 본다.
2. 본문의 페이지 링크를 ⌘-클릭해서 새 탭으로 열리는지 본다.
3. 탭을 끌어 순서를 바꿔 본다.
4. 인스펙터의 제목을 눌러 해당 제목으로 스크롤되는지 본다(제목이 있는 페이지에서).
